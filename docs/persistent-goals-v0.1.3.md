# v0.1.3 增量实现记录

状态：进行中，尚未达到发布或 v0.1.3 验收状态。更新发生在现有项目中，未重建项目或修改真实用户数据库。

## 已实现的内部基础

- `server/goals/work-scopes.ts` 新增 Area、project/ongoing Workstream 的持久化、同一 owner 约束、列表、改名、状态及版本检查。ongoing 不能标记 completed。归档前拒绝仍有未解决目标、活跃尝试或待确认停止的范围。
- 目标数据库迁移至 schema 8：按 owner 创建确定性的“未分类”Area 和兼容 Workstream，旧 Goal 通过关联表归属，不重写原有目标、任务、运行、预算或成果记录。新 Goal 可显式关联同 owner 的活跃 Workstream；未提供时使用兼容范围。
- 内部就绪任务查询、计划/工作准备、派发 outbox 和根运行首次准入检查父范围状态。父层恢复不修改子层暂停状态；暂停范围的待派发项不会阻塞其他范围的队列。已开始的运行沿用原有运行控制语义。
- 自动化测试覆盖旧数据库重开、原 ID 和预算用量保留、所有者隔离、两范围就绪任务、父子暂停、派发过滤、归档保护以及 ongoing 状态约束。范围状态检查和首次运行预算预留在同一数据库事务中执行。

- 无业务 Goal 的单事项通过明确标记的内部执行容器复用现有任务、outbox、尝试和成果检查；机器人可见的事项上下文不包含该内部容器的 Goal ID。周期事项使用 `(workstream, routine, occurrence)` 唯一键并可在重启后重复取回。
- 新事项要求预先设置单事项和用户全局执行上限；ongoing 还必须绑定已配置的周期上限。同一持续事务下有 Goal 和无 Goal 工作的预留共同计入周期额度；全局额度配置后，现有 Goal 的执行也计入。未配置全局额度的旧项目 Goal 保留旧行为，正式启用前必须完成宿主级全局预算配置和迁移策略。
- 新派工持久绑定工作线程到 Workstream，拒绝跨 Workstream 复用同一线程。该绑定不能证明历史线程消息、全局记忆或文件已隔离，宿主仍需提供独立会话和资源授权。
- 内部调度按 Workstream 轮转，每次最多准备该范围的一项；测试覆盖一个范围有 101 个就绪事项时另一范围仍有调度机会。该轮转尚未加入截止时间、优先级或跨重启持久游标。
- 新增负责人复核执行、绑定的逐项 verdict、证据快照和停止对账。确定性检查与负责人复核均通过后，重新读取成果并确认哈希，再可将当前任务标记成功；fail 和 unknown 分别记录为要求修改或待澄清，不视为通过。
- 复核通过的成果以原始字节与哈希保存在目标数据库；下游尝试绑定前置复核及成果版本，并可按受限分块工具读取快照。上游登记了新版本或状态失效后，准入、结果接收和调度审计会阻止旧输入继续推进。每次复核的快照总量暂限 64 MiB；外部源文件变化尚无自动监听，必须经后续检查或新版本登记才能发现。
- `host-service.ts` 可在宿主提供身份、权限、文件根及停止证明后，将目标存储、原生协调器和定时调度组合；已实现检查与复核收尾的内部自动推进，隔离假宿主覆盖单事项真实测试文件闭环。该服务已在仅供密封测试实例使用的双重开关下接入 `server/index.ts` 与机器人工具路由；正式个人环境仍未启用。
- 工作范围管理和事项状态总览路由已接入 `server/index.ts` 的显式预览开关，默认关闭，仅个人环境的已配对管理员会话可访问。侧栏提供预览入口、范围筛选和创建范围/Workstream；隔离真实服务中已验证创建 Area、ongoing Workstream 和未配对请求被拒绝，隔离浏览器检查了侧栏布局。该预览不启动目标调度，也不是可用的完整任务入口或正式发布。
- 原生 agents 工具目录与代理环境增加按 plan/work/review 角色显示的目标工具，宿主适配器可依据实际运行和当前会话身份分配角色及派发工具；跨角色、跨机器人和伪造目标参数的调用在隔离测试中被拒绝。默认不向普通对话暴露；密封测试实例现已在真实机器人运行中设置角色并注册内部工具路由；正式对话中仍不可调用。

2026-11-02 侧栏、目标模块、范围路由、运行时与代理桥接回归 319 项通过；随后目标角色代理和身份派发专项测试通过，最新服务器重新打包、定向 TypeScript 与 lint 检查通过。此前的服务器包在无 node_modules 的隔离目录通过启动、代理路径、MCP 和备份 worker 冒烟测试；最新包尚需重新执行完整发布检查。无 Goal 测试使用隔离假执行器，覆盖实际测试文件、自动准备复核、复核通过和事项成功，不代表真实模型交付。上游一次性隔离服务验证了预览范围接口和配对权限；目标执行模块未接入该服务，故这不是目标功能验收。

## 2026-11-02 隔离宿主接线进展

- 增加按 Workstream 和事项隔离的受控目录引用及防链接检查；规划机器人可获取对应事项的工作区引用。原生线程使用确定性 ID，重复创建会拒绝碰撞，便于崩溃后的幂等恢复。
- 仅密封测试实例通过预览和运行时双开关启用目标创建、协调器准入、工具路由、工作及复核准备。真实环境默认仍关闭；执行停止证明目前保守返回未确认。
- 发现客户端根任务首轮被映射为普通来源，导致真实模型启动前取消；现将已登记客户端根的运行状态正确投影为 running，并补回归测试。
- 复核角色可按块读取本次授权成果：读取受限于工作区，校验登记哈希，拒绝其他成果和已篡改文件，读取后再次确认复核身份及证据未变。
- 隔离验证通过：任务/工作区测试 160 项通过（1 项跳过），目标模块与范围路由 41 项通过，协调器 94 项通过。隔离服务验证了重复提交仅创建一次、规划任务开始运行以及未授权内部工具调用返回 401。最新服务器包也在无 node_modules 的隔离目录通过启动与代理、MCP、备份 worker 冒烟检查。真实模型隔离试运行发现并修复首轮状态投影错误及同步启动异常未报告的问题；改用实际可执行文件并配置测试代理后，真实模型已读取上下文、生成工作区引用、提交计划并启动工作任务。真实模型已完成合成事项：实际文件登记、自动检查、负责人读取文件及复核通过，事项状态变为 succeeded。目标级检查和汇总交付仍未实现。以上不等同正式发布。

- 预览接口现可按已配对 owner 读取和设置全局及持续事务周期执行预算，并返回已预留用量；隔离测试验证伪造 owner、跨用户读取和修改均被拒绝。

## 2026-11-02 聊天入口试用增量

本机试用通过 `/index.html?persistent-work=1` 接入原版聊天：在输入框填写要求后明确点击“交办为任务”，普通发送仍是普通对话。界面展示任务执行次数及总上限；首次交办才初始化缺失的总上限，不覆盖已有配置。任务暂归入“未分类”，附件和自动识别任务意图尚不支持。重复提交的网络重试使用相同命令 ID，避免重复创建。已关联来源对话的新任务只显示在对应对话；历史未关联任务按所属助手显示。

任务完成并复核后可在右侧阅读已批准的文本快照，其他格式仍可下载。在线预览限制大小、文件类型和 UTF-8 编码；不会执行报告中的 HTML。关闭报告后回到对话，但报告内容不会自动加入下一条聊天。原有范围管理和下载入口保留。

目标数据库迁移至 schema 9，新增可选来源对话关联；不重写旧任务。以上能力仅在显式开启的本机试用运行时提供，并不代表周期自动执行、目标汇总、完整隔离或 v0.1.3 正式发布已完成。
