# 三阶复盘：持续目标系统开发续作

## 第一阶：发生了什么

实现内部根运行幂等入队、目标执行预留与准入、派工 outbox、目标和首版 DAG 持久化、业务任务派工预留、运行事件投影、单写入锁，以及实际文件的授权解析、哈希、登记和检查，并通过隔离数据库和运行时测试。系统仍未接入宿主和用户界面，未达发布状态。

## 第二阶：为什么

目标数据库与 runtime 数据库不能原子提交，派工需要稳定键和重复受理；执行次数也必须在根、子运行和续跑的真正启动前预留。为避免将未经宿主授权的路径投入使用，新增能力只保留内部入口，并在预算钩子缺失时不启动。

真实底座测试中，首选测试模型不受当前账号支持，四分钟重试又因响应慢超时；延长等待后，两位专家均完成并触发负责人汇总。应保留失败和超时证据，不能只记录最终成功，也不能把原生协调等同于持续目标产品验收。

## 第三阶：下一次如何改进

继续按真实的纵向流程完成宿主授权与组合、计划提交身份验证、对账和调度，再接入界面及真实模型验收。对于跨库预留后的崩溃，要明确区分保守占额和实际启动，补全对账后才能对外宣称预算准确。当前流程仍在实现中，不抽取为通用 skill。
