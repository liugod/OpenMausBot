# 三阶复盘：无业务目标事项和预算

## 第一阶：发生了什么

在原目标执行链内增加明确标记的单事项执行容器、周期去重、全局和持续事务周期预算以及新线程范围绑定。隔离测试运行事项、登记真实测试文件并执行文件检查，也覆盖重启重放和预算累计。用户确定最终发布目标是本机个人使用；尚未发布。

## 第二阶：为什么

现有尝试、outbox 和成果模型以 Goal ID 为外键，内部容器能保持已有数据结构并避免无预算快捷通道；对机器人隐藏容器 ID，避免将内部实现误当业务 Goal。只限制单事项额度会让新事项重置预算，因此同一 owner 和周期的执行需在同一数据库事务中累计。线程绑定只能阻止新跨范围复用，不能消除历史消息或全局记忆污染。

## 第三阶：下一次如何改进

先为宿主确定可信的用户、独立会话、工作目录和预算周期来源，补齐上下文版本与真实授权，再接入路由、界面和审核交付，并在隔离本机实例执行真实模型验收。旧 Goal 在未配置全局额度时仍沿用旧预算，不能据此宣称全局预算已在生产生效。实现和部署流程尚未稳定，不提炼通用 skill。
