# GSD 双向控制三阶复盘

## 第一阶：做了什么

为已绑定的 GSD 任务记录实际主控派工回执、助手与独立会话；为暂停、继续和需求变更增加持久化指令与冲突检查。隔离协调服务使用脚本化助手验证了原会话定位、暂停交接证据、继续、变更与重复请求；真实 Codex 另行验证了创建派工、需求变更和协作暂停。模型开始恢复与完整恢复的结果仍须分别确认。

## 第二阶：为什么

主控派工后的回执与真正执行不是同一个状态。暂停既需要原执行正常结束，也需要新的 GSD 交接文件；后台异步作业仍需另外核查。需求变更涉及文件与数据库两个持久化边界，发送前后都可能发生竞争或中断，不能将提交或文件变化单独当作用户意图已落实。

## 第三阶：下次如何复用

使用稳定任务和命令身份、唯一派工标记、事务认领和真实回执；发生中断时先查现有回执，不能盲目重发。对照路线图、需求、状态文件版本处理冲突，记录人工或主控核对的依据；不明状态保留待核对。上线前用独立服务、临时仓库和模拟助手覆盖异常，再分别验证真实 Codex 能否按技能完成实际工作。

本次回归 14 项通过，类型检查通过；升级前使用 SQLite 在线备份，升级后核对完整性和已有表的记录数量。相关可复用的协调及执行流程已整理进 `openmaus-gsd-bridge` 和 `openmaus-gsd-worker` 技能。
