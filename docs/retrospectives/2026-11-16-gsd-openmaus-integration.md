# OpenMausBot 与 GSD 本机接入复盘

## 第一阶：发生了什么

在现有主控和软件开发助手上安装专用技能，通过独立 Git worktree 调用本机 GSD Core 1.21.0，保留原有机器人和数据。自动测试在独立服务及合成仓库中运行；单个代码助手的真实 Codex 运行已完成 `gsd-fast` 样例。主控真实派工测试曾到达代码助手，但因助手对测试文本的字节数产生疑问而暂停，不应将派工本身当成完成。

## 第二阶：为什么

OpenMaus 试用服务使用受控 PATH，普通终端能找到 Git 不代表机器人也能找到；因此本机记录 Git 路径并在服务启动时注入。GSD 输出、OpenMaus 派工状态和实际成果是不同的证据，任何一个都不能单独证明最终交付。隔离环境测试还揭示，自动生成的执行计划可能引入多余约束，需要以用户原始验收条件为准。

## 第三阶：下次如何复用

复用主控与执行助手的两个技能，先核对仓库根目录、干净 HEAD 和权限，再创建工作树、交办、读取实际成果与测试。测试使用独立服务器、合成仓库和独立状态目录；安装器须预检同名技能并读回配置。遇到需求冲突或执行中断时报告真实状态，不把阶段进度、准备成功或任务派出写成完成。多阶段恢复、跨系统状态同步和预算硬限制仍需独立实现及验证。
