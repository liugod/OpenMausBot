# 三阶复盘：负责人复核与成果版本

## 第一阶：发生了什么

新增负责人复核尝试、逐项结论、检查和成果版本快照、复核取消对账、复核失败状态，以及文件复检后完成任务的内部流程。隔离假执行器完成一次无业务 Goal 事项的文件登记、检查和复核；另测试失败、未知结果、成果变更、范围暂停和未停止的复核运行。原生服务隔离实例通过健康检查，临时数据已清理。

## 第二阶：为什么

执行器完成或自称成功不能证明业务条件达成。复核必须绑定真实的当前运行、具体任务、条件和证据；未知与失败不能成为通过。复核运行也会消耗预算并须参与取消对账；范围暂停后的检查和最终收尾也应等恢复。由于目前没有安全的下游输入快照/失效传播机制，前置任务成功不足以证明后续执行所读文件仍是被验证的版本，因此先阻止有依赖的派工。

## 第三阶：下一次如何改进

补齐受授权的成果快照、下游输入版本记录与失效传播，然后自动执行检查、复核和收尾，再接入宿主能力、用户界面与真实模型验收。注意文件系统和数据库不能天然原子提交，不能仅凭一次哈希读取声称后续消费必然安全。完整回归执行期间不要同时修改被测代码，否则可能组合出旧模块与新测试，需固定版本后重跑。该流程仍未接入产品且尚未通过发布验收，不提炼通用 skill。
