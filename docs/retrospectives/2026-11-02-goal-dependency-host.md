# 三阶复盘：依赖成果与宿主自动推进

## 第一阶：发生了什么

将复核通过的文件字节和哈希存入目标数据库，为下游尝试绑定前置复核与成果版本，并提供受当前运行身份约束的分块读取；前置成果登记新版本后，阻止旧输入继续执行并标记受影响事项。增加宿主服务适配器，组合协调器、授权、预算、调度、自动文件检查和复核收尾。隔离假宿主完成了单事项文件、检查、复核和完成闭环；范围管理接口与侧栏接入默认关闭的本机预览，隔离实例验证了配对权限、创建范围与布局。机器人工具目录、代理角色传递和基于运行身份的派发器已经增加，真实宿主还未接线。

## 第二阶：为什么

原文件路径可变，单次检查后下游可能读到不同内容；将获批字节固定下来，并在准入及结果接收时核对前置任务和版本，可以避免静默采用错误的输入。原生协调器把首次运行根节点投影为 source，不能错误地只接受 running；文件登记过程也可能遇到无关运行状态事件引起的版本增长，应在同一任务、尝试、需求及计划版本仍有效时受控处理。

## 第三阶：下一次如何改进

将宿主适配器接到正式服务身份、MCP 工具和原生界面，完成自动返工、目标级交付和真实模型验收，再安装本机版本。外部文件变化不能自动等同于已登记新版本；需要可靠的变更检测与重评估。当前代码未接入真实宿主、未安装，流程尚不适合提炼为通用 skill。
